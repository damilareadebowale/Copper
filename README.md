```markdown # Human Copper Chaperone Screen from AlphaFold Structures A structure-based screening workflow to identify candidate human copper chaperones from the AlphaFold human proteome by combining: 1. **Cysteine motif detection** 2. **SG–SG distance filtering** 3. **Surface-depth analysis using MSMS** The workflow is designed to recover known copper-binding cysteine motifs and prioritize new proteins with **surface-accessible cysteine pairs** that could support copper coordination. --- ## Overview Copper chaperones often contain **closely spaced cysteine pairs** that are sufficiently exposed to interact with solvent and potentially coordinate Cu(I). This project screens the AlphaFold human proteome for such motifs in four steps: - **Step 1**: scan the AlphaFold library and account for all input structures - **Step 2**: identify proteins containing at least two cysteines with SG atoms - **Step 3**: compute all pairwise SG–SG distances and retain candidate pairs in a geometric window - **Step 4**: compute burial/surface proximity of retained pairs using MSMS The output is a table of cysteine pairs annotated with: - SG–SG distance - depth of each SG atom to the solvent-excluded surface - depth of the cysteine-pair midpoint to the surface --- ## Workflow ### Step 1. Input and accounting **Action** Iterate through every `.pdb` file in the AlphaFold library. **Metric** Count total proteins/models started. **Validation** Confirm that the benchmark copper proteins are present in the library: - **ATOX1** — `O00244` - **CCS** — `O14618` - **SCO1** — `O43819` - **SCO2** — `O75880` - **COX17** — `Q14061` - **COX19** — `Q49B96` --- ### Step 2. Parse each PDB and extract cysteines with SG atoms **Action** For each structure, identify all residues annotated as `CYS` that contain an `SG` atom. **Filter** Discard proteins/models with fewer than **2 cysteines**. **Metric** Count proteins/models with **≥2 Cys(SG)**. **Validation** Verify that the benchmark proteins pass this step. Example question: > Did we detect cysteines in ATOX1, CCS, SCO1, SCO2, COX17, and COX19? --- ### Step 3. Pairwise SG–SG distances (2.0–5.5 Å) **Action** For every protein/model that passed Step 2, compute all pairwise distances between cysteine sulfur atoms (`SG–SG`). **Filter** Keep only cysteine pairs with: - **SG–SG distance ≥ 2.0 Å** - **SG–SG distance ≤ 5.5 Å** **Metric** Count proteins/models with **≥1 valid SG–SG pair**. **Output** Emit **one row per retained pair** to a CSV for inspection and downstream analysis. A protein/model may contribute multiple rows. **Validation** Verify that known benchmark motifs survive this step. Examples: - **ATOX1**: Cys12–Cys15 - **CCS**: Cys22–Cys25, Cys141–Cys227, Cys144–Cys227, Cys244–Cys246 - **SCO1**: Cys133–Cys137 - **SCO2**: Cys169–Cys173 - **COX17**: Cys23–Cys24, Cys26–Cys55, Cys36–Cys45 --- ### Step 4. Depth calculation via MSMS (surface proximity) **Action** For proteins/models that survive Step 3: 1. Generate `.xyzr` coordinates using robust atom radii 2. Run **MSMS** to triangulate the **solvent-excluded surface** 3. Build a **KDTree** from surface vertices 4. Compute: - **res1_depth**: distance from cysteine 1 SG to the nearest surface vertex - **res2_depth**: distance from cysteine 2 SG to the nearest surface vertex - **motif_center_depth**: distance from the midpoint of the cysteine pair to the nearest surface vertex **Result** A CSV containing every proximity-valid cysteine pair in the human proteome, annotated with surface-depth information. --- ## Recommended execution order Run the workflow in two phases: 1. **Step 1–3 first** - generate the accounting tables - generate the SG–SG pair table - validate benchmark motif recovery 2. **Step 4 second** - run MSMS only on Step 3 survivors - compute depth features - prioritize surface-accessible candidates --- ## Expected outputs ### Step 1–3 - `step2_counts.csv` Per model/file summary of cysteine counts - `step3_counts.csv` Per model/file summary of total candidate pairs and retained pairs - `step3_pairs_check.csv` One row per retained SG–SG pair ### Step 4 - `step4_depths.csv` One row per retained SG–SG pair with: - `pdb_id` - `filename` - `chain1`, `res1`, `icode1` - `chain2`, `res2`, `icode2` - `sg_sg_dist` - `res1_depth` - `res2_depth` - `motif_center_depth` --- ## Notes on accounting This project can be summarized in two different ways: ### 1. Per file/model Each AlphaFold PDB file is treated as an individual structural model. ### 2. Per UniProt accession Multiple AlphaFold fragments/models corresponding to the same accession are collapsed under one `pdb_id`. For screening and geometry calculations, **each filename should be treated as a separate model**. For downstream ranking, the results can be collapsed to **one best pair per UniProt accession**. --- ## Benchmark set used for validation ```python BENCH = { "O00244": {"name": "ATOX1", "pairs": [(12, 15)]}, "O14618": {"name": "CCS", "pairs": [(22, 25), (141, 227), (144, 227), (244, 246)]}, "O43819": {"name": "SCO1", "pairs": [(133, 137)]}, "O75880": {"name": "SCO2", "pairs": [(169, 173)]}, "Q14061": {"name": "COX17", "pairs": [(23, 24), (26, 55), (36, 45)]}, "Q49B96": {"name": "COX19", "pairs": []}, } ``` --- ## Candidate prioritization After Step 4, candidate cysteine pairs can be prioritized using combinations of: - **SG–SG distance** - **minimum depth** of the two cysteines - **maximum depth** of the two cysteines - **motif_center_depth** Typical use cases: - keep pairs where at least one cysteine is highly surface-exposed - keep pairs where both cysteines are not deeply buried - collapse multiple fragment-level results to the **single best pair per UniProt** --- ## Dependencies Typical requirements: - Python 3 - `numpy` - `pandas` - `scipy` - `biopython` - `msms` - `pdb_to_xyzr` Optional: - `freesasa` for SASA-based prefilters --- ## Example high-level usage ### Step 1–3 ```bash python3 screen_step1_3.py \ --pdb_dir /path/to/alphafold_human_proteome \ --out_dir out_step1_3 \ --workers 4 ``` ### Step 4 ```bash python3 step4_depth_msms_mp.py \ --pdb_dir /path/to/alphafold_human_proteome \ --pairs_csv out_step1_3/step3_pairs_check.csv \ --out_dir out_step4 \ --workers 4 ``` --- ## Troubleshooting ### Duplicate AlphaFold fragments for one accession Use **filename → full path** mapping, not just accession → path. Different fragments/models can share the same accession but differ in residue coverage. ### `sg_not_found` in Step 4 This usually indicates a mismatch between the file used in Step 3 and the file opened in Step 4. ### MSMS failure on a single protein If MSMS fails for an isolated case, the model can either: - be skipped, or - be rerun separately with reduced surface density and patched back into the Step 4 table. --- ## Summary This workflow identifies candidate copper-binding cysteine motifs in the AlphaFold human proteome by combining: - **chemical plausibility**: cysteine sulfur pairs - **geometric plausibility**: 2.0–5.5 Å SG–SG spacing - **structural accessibility**: MSMS-derived depth to the protein surface The benchmark set is carried through the workflow to ensure that filtering remains biologically meaningful while the candidate set is reduced. ```
